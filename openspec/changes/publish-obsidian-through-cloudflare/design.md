# Cloudflare Obsidian Publishing Design

## Context

See proposal.md for motivation. This checkout uses `site.New`, `site.PagePaths`, and `site.Export` to render public HTML with Go, then `scripts/build-cloudflare.mjs` packages it for Workers Static Assets. `.github/workflows/cloudflare.yml` already validates, archives, deploys, and verifies one tested artifact. Production and PR previews have independent concurrency groups. No Obsidian implementation exists in this checkout; PR #390 contains reusable validation and publisher code on an older branch.

The user selected GitHub Actions after considering both build services and accepted a couple minutes between edit and publication. That selection does not establish a preference to avoid Actions. The public repository's standard runners currently have no minute charge; runner duration, concurrency, retries, and artifact storage still deserve measurement. The two production jobs inspected in this discussion took 56 and 59 seconds; that is a baseline, not a prediction for this new pipeline. Older storage and QA evidence on PR #390 does not prove the replacement system.

## Goals / Non-Goals

**Goals:** Preserve static rendering and the existing Go renderer; publish content without Git commits; provide an always-available private staging site; keep unpublished posts and images private across serving, logs, and artifacts; retain file-level fallback across ephemeral runners; expose trustworthy publication status; make source preparation independent of the build-service adapter.

**Non-Goals:** Running Go on Cloudflare, porting templates to JavaScript, rendering Markdown on visitor requests, implementing Cloudflare Builds now, adding other content sections, or deleting legacy Google/AWS resources.

## Decisions

### Storage and source revisions

Use three Standard-class R2 buckets in the current site account: private `justindfuller-obsidian-source`, public-image-only `justindfuller-obsidian-media`, and private `justindfuller-obsidian-state`. Only the public image bucket receives `media.justindfuller.com`; disable r2.dev access for all three. Keep source and state separate to enforce read-only source access for CI while allowing CI to persist accepted state and private build archives. Upload all original image bytes to the private source bucket; a separate production promotion command copies only eligible referenced images into public storage. Uploading the entire vault image tree publicly would expose unpublished assets.

The source bucket stores immutable Markdown at `markdown/v1/<sha256>.md`, complete revision manifests at `snapshots/<revision>.json`, and one mutable `latest.json` pointer. A version-1 snapshot contains `version`, a `files` map keyed by logical root Markdown filename with `key`, `sha256`, and `size`, and an `images` map keyed by logical `image/...` path using the existing asset record fields `sha256`, `md5`, `size`, `contentType`, and `key`. Derive the revision from canonical manifest bytes: sorted maps, stable encoding, no timestamps in hashed content. `latest.json` contains `version: 1` and `revision`; publication timing is separate private status data. Reject unsupported versions, unknown control fields, unsafe paths, duplicate keys, and mismatched keys or hashes. Keep the old image-manifest guardrails of 10,000 image records and 2 MiB for image metadata; cap the complete snapshot control document at 8 MiB and the pointer at 1 KiB as documented protocol limits. These are source-wide control-document failures and do not introduce a per-post Markdown writing rule.

Upload and verify referenced objects before writing the snapshot and then replacing `latest.json`. Retain unchanged Markdown objects. Preserve each present Markdown filename in the manifest even when its bytes are invalid UTF-8 or its metadata is invalid; Go must observe that invalid revision rather than infer deletion. Source read/integrity failures block activation. Invalid image bytes retain the previous verified image mapping for that logical path when available, otherwise omit that mapping and report the issue; unrelated uploads continue. A file truly absent from a complete scan loses its source ownership. Do not garbage-collect remote objects in v1.

Private originals and promoted public images use immutable `v1/<sha256>.<extension>` keys with verified SHA-256, MD5, size, and MIME metadata. The R2 S3 ETag is not an assumed MD5 contract: compare explicit custom metadata and actual size/type. Go uses metadata checks once per unique referenced object and never reads image bodies. The Mac validates one image at a time, retaining the existing 20 MiB limit and safe SVG restrictions. The dedicated promotion command copies verified private objects referenced by the effective accepted, nondraft production collection and verifies public destination metadata before production deployment; invalid references remain isolated. Use R2 object copy where supported or bounded streaming outside Go, without retaining the vault's images in memory. Never promote images merely because they appear in a source snapshot, staging build, draft, or nonprod post.

Public image responses retain `Cache-Control: public, max-age=31536000, immutable`; production HTML retains the existing static-serving cache behavior. Do not cache public image 404 responses so an early request cannot hide a later upload. Nonprod renders use same-origin `/__obsidian/media/v1/<sha256>.<extension>` URLs. A small Worker handler streams authorized GET/HEAD image requests from the private source R2 binding, restricted to supported hash keys in the deployment's image allowlist; it cannot serve Markdown, manifests, or arbitrary bucket paths. Run this handler locally through a loopback Cloudflare dev gateway with explicit private-source access. Production has no private-source runtime binding or private-image route. This adds runtime image streaming only for private previews; Markdown remains rendered at build time.

### Post targets and persistent private staging

Require `environment: nonprod | production`. Production posts are eligible in production, staging, PR previews, and local development; nonprod posts are eligible in staging, PR previews, and local development only. Preserve `draft: true` exclusion in every environment, including overwrite masks: a post intended for review uses `environment: nonprod` and `draft: false`. Post targeting and deployment mode are separate values. Migrate old `prd` to `production`, and old `pr`/`local` to `nonprod`, using an explicit local metadata migration/check; do not silently accept legacy aliases. Moving a previously accepted post to nonprod removes its external public ownership on the next successful production reconciliation even when accepted production fallback exists; additive routes disappear and overwritten Git routes return. Eligibility changes are applied before per-file fallback so old target eligibility cannot leak an unpublished revision.

Use a separate `justindfuller-site-staging` Worker at `staging.justindfuller.com`, continuously serving the latest verified main-code/staging-content deployment independently of PR lifecycle. Disable its workers.dev URL and version preview URLs unless later required. Before any private upload, configure a Cloudflare Access Worker destination protecting the entire staging Worker, plus a `preview_worker` destination covering native previews of `justindfuller-site`. This protects alternate immutable and alias preview URLs without placing production apex/www behind Access. Hostname-only Access and noindex alone are insufficient privacy boundaries. Keep PR refresh explicit and local serving bound to loopback.

Restrict the human Allow policy to one explicitly configured owner email, authenticated through Access email one-time PIN or the owner's selected identity provider. Choose the email during provisioning rather than infer it from Git metadata. CI verification uses a dedicated expiring Access service token in a separate Service Auth policy, with `CF-Access-Client-Id` and `CF-Access-Client-Secret` supplied only to protected requests. No public bypass or everyone policy is allowed. Rely on platform-enforced Access authorization, not client-supplied identity headers. Access protection must cover HTML, static assets, sitemap/feed output, and private image requests before any response body is delivered.

Fail deployment closed when the required Access application/policy or protected destination cannot be verified. Prove the boundary first with nonsensitive sentinel assets; before uploading nonprod content, check the configured identity/policies and anonymous denial on every enabled hostname, alias, and immutable URL. Deployments repeat the applicable policy and route checks, then use service authentication for exact-byte verification and test denied requests after authenticated requests. Staging/PR responses use `Cache-Control: private, no-store` and noindex, without shared response caching or service-worker storage. Cloudflare's Cache API is unavailable for Workers fronted by Access; private preview caching is not a prerequisite. Public production caching remains intact. The initial one-user Access setup should fit its free plan, subject to account verification at rollout.

### Mac publisher and dispatch

Expand PR #390's publisher to watch all eligible `Blog/` content. Use a 60-second quiet debounce, a two-minute maximum batch age, startup reconciliation, and a five-minute catch-up scan. Serialize reconciliations and retry dirty paths after an interrupted scan. Manual publish bypasses the debounce. Five-minute scans upload or dispatch only when actual content differs; they do not create periodic builds. A sleeping Mac or closed Obsidian delays uploads until the next reconciliation.

Use R2's S3 endpoint and region `auto`; keep its credentials in asynchronous macOS Keychain entries. Preserve the existing plugin installation identity during migration, update its displayed name and commands, and require explicit R2 settings rather than interpreting old S3 destinations as Cloudflare. Store a separate fine-grained GitHub dispatch token in Keychain, selected only for this repository with Actions write and an explicit expiry. This is a new publisher credential, not a replacement for the machine's retained authentication setup. GitHub does not restrict that permission to one workflow; the client hardcodes the repository, workflow, and `main` ref and never accepts arbitrary workflow commands from note content.

Dispatch the existing `cloudflare.yml` workflow with a new `publish_kind=content` input after activation; default manual dispatch remains a normal site build. A content request reconciles both staging and production and skips each unchanged target independently. Any revision identifier is informational, because deployment preparation reads the current source pointer inside the relevant target's concurrency boundary. Persist a pending dispatch locally without secrets or note bodies. Retry transient upload/dispatch errors with exponential backoff capped at five minutes, honoring provider retry headers; authentication failures remain actionable and do not loop rapidly. After a restart, compare private reports for both targets before redispatching so an ambiguous successful API response can be reconciled. Display uploaded, queued, verified, degraded, and failed states separately for each target; one target's success does not clear the other's pending failure. New protected issue fingerprints and recovery produce deduplicated Obsidian notices, using a separate state-bucket read-only credential in Keychain.

### Build-time overlay and durable fallback

Extract PR #390's source-independent validators, merge logic, image resolver, and regression fixtures into the current site. Avoid its polling loop, Drive/GCS readers, App Engine configuration, and CloudFront provisioning. Go loads Git entries once and builds an immutable effective programming collection consumed by both the HTTP handlers and exporter path enumeration. Add an explicit prepared-overlay input to local serving and static export; no input retains current Git-only behavior. Environment selection is explicit, not inferred from App Engine services. Generate the effective programming list, canonical routes, real draft-mask 404s, and sitemap from that same collection. The current exporter has no synchronized sitemap path, so add one that includes the site's existing public route inventory plus eligible external routes. Preserve homepage feature behavior.

Expose portable prepare, export, and publication-record commands. Preparation reads `latest.json` once, pins the immutable manifest, verifies Markdown bodies, loads accepted state, and applies the prior validation contract. Store accepted Markdown bytes and image metadata privately, indexed by logical file identity, with accepted revision, ownership, draft masks, issue fingerprints, and deployment receipt. Re-render and revalidate retained candidates against the current Git routes, template code, and policy version; do not cache old rendered HTML as the content authority. After route ownership changes, remove an old route only when its replacement is accepted. Reject all conflicting new claims consistently and retain a prior accepted resolution if present. A confirmed absent filename removes its external claim; a missing referenced object or failed read is a source failure, not deletion.

Persist production state under `production/`, staging state under `staging/`, preview state under `pr/<number>/`, and local state in an ignored private local directory. Staging/preview state never seeds production. Revalidate eligibility before fallback and calculate each target's output separately, including image URL mode, route masks, and sitemap. On source-wide outage, content-only runs keep the affected target's deployed site; code builds may reuse its accessible accepted content and produce a degraded report. If accepted state cannot be loaded after installation, stop that target before deployment. Explicit operator bootstrap records an empty initial state and uses Git-only output; missing credentials must not silently select bootstrap. State schema or validation-policy incompatibility is actionable and requires revalidation or migration before publishing.

### Actions integration, concurrency, and verification

Extend the existing workflow rather than create a second production deployment authority. Both content dispatches and code deployments share its existing `cloudflare-production` concurrency group with cancellation disabled; staging uses `cloudflare-staging` and PR work keeps its per-PR group. Move serialization to the appropriate target jobs so staging-only work does not occupy the production deployment queue. Do not rely on FIFO ordering: GitHub may replace a pending run. Each staging/production reconciliation checks out current main and reads the latest complete source after acquiring its concurrency boundary, recording the actual checked-out SHA and pinned source revision; queued events must not restore stale code or content. Content dispatches reject any non-main ref. Share compatible code-validation receipts and dependency caches across target jobs; later source edits remain pending for subsequent reconciliation.

A content run first prepares each effective overlay using the Go toolchain/cache. An identical source/code receipt exits early; a changed source with unchanged effective output updates diagnostics and accepted reconciliation metadata without `npm ci`, full rendering, or deployment for that target. A nonprod-only edit normally rebuilds staging and skips production; a production edit can update both. Code builds retain the full existing checks. Changed targets perform content validation, export/link/privacy checks, mode validation, artifact checksumming, deployment, and strict live verification: anonymous production checks on apex/www, authenticated staging/PR checks plus anonymous-denial checks on private URLs. They need not rerun the entire code test suite for an unchanged main commit already proven by CI. If that commit lacks a successful compatible code-build receipt, use the full code validation path. Treat draft masks and routing as part of the output digest, not just visible post bodies.

Prewrite a private candidate publication journal and state object before deployment, capture the previous serving version, then deploy the same tested artifact and run the existing exact-byte checks. Promote the accepted-state pointer only after verification. Record code SHA, source revision, effective-content digest, policy version, artifact checksum, Actions run ID, and Cloudflare deployment/version IDs. Reconcile an interrupted promotion against the active serving identity before another deployment; an orphan candidate is never automatically accepted. A failed build leaves the prior deployment. A failed live check attempts restoration of the captured prior version followed by its artifact checks; failed or unverified rollback is an actionable deployment incident. Required state writes use bounded retries and leave an explicit journal when their result is ambiguous.

Apply candidate journals, verification, state promotion, and rollback separately to staging, production, and each PR. A staging failure leaves the previous staging deployment available and does not roll back successful production or corrupt its state. PR builds include a source snapshot on existing events; provide a manual preview-refresh input that validates an open, same-repository PR, builds its current head with both post targets and noindex, and uses that PR's existing concurrency group and cleanup policy. Keep workflow control logic on trusted main and private content away from untrusted fork code. Fork/Dependabot jobs use fixtures and no secrets. Local commands explicitly prepare both post targets, bind serving/gateway ports to loopback, and can run Git-only without credentials. Do not automatically dispatch all open previews on vault edits.

### Privacy, credentials, and usage

The Mac uploader has source-bucket object read/write only; it has no public-media write, state write, or domain/deployment authority. CI reads private sources, uses a separate public-media write credential for production promotion only, and uses separate state-bucket read/write credentials. A separate operator/publisher report credential reads state only. R2 standard object read/write tokens are bucket-scoped and also permit deletion; routine uploader/promotion implementations do not delete, and v1's hash-addressed immutability is an application invariant, not a claimed credential guarantee. Protected staging/preview Workers use the private R2 binding only through their narrow image handler; an R2 binding itself is not claimed to be read-only. Provisioning credentials manage staging domains, buckets, and Access applications separately. Preserve the existing production deployment token's authority; provision a separate staging deployment token with the narrowest Cloudflare-supported scope, and document any account-level permissions that cannot be restricted per Worker. Access verification/service credentials remain separate from deployment credentials.

The repository and Actions logs are public. Store full file diagnostics privately in R2 and expose them through read-only local tooling and the Mac publisher. Public logs and receipts show opaque hashes, safe categories, counts, root preview URLs, and deployment identities; omit nonprod paths/titles/slugs and sanitize SDK, renderer, and verifier errors. Access does not protect GitHub artifact downloads. Only production assets that already meet the public-output policy and sanitized receipts can be Actions artifacts. Store tested staging/PR archives, including generated HTML and verification manifests, privately under state-bucket `artifacts/staging/<run>/` and `artifacts/pr/<number>/<run>/`; deployment jobs retrieve and verify those exact checksummed archives. Never upload private HTML, sitemap, source maps, inline post data, overlays, reports, raw Markdown, or source manifests to publicly readable artifacts. Apply dependency scripts before injecting source secrets or private content, and avoid environment dumps and private file contents in command output.

Keep public artifact retention at the current 14-day default initially and apply a 14-day lifecycle to private build archives only, excluding accepted-state journals, source objects, and current verification/rollback records. Record per-target batch frequency, runner duration, build/deployment frequency, skips, retries, latency, and R2/Worker operations, including image promotion and private image reads. Automatic staging adds build work even when production is unchanged; combine dispatches, reuse proven code checks/caches, and retain independent no-op decisions. Review observed usage after two weeks and after a material change in publishing volume; compare both build services equally if cost, reliability, or latency becomes unsatisfactory. Retain the prior approximate $5/month Cloudflare planning envelope with alerts rather than automatic shutdown as a memory-derived default to confirm at rollout; it is not a cap or a newly selected user preference in this discussion.

## Risks / Trade-offs

- A debounce and build queue can exceed a couple minutes during continuous edits, outages, or competing deployments. Measure actual upload-to-verification timing; show queued status rather than claim a fixed freshness guarantee.
- A complete snapshot and persisted fallback add control objects, but avoid mixed revisions and content loss on fresh runners. Test interrupted uploads, missing objects, file renames, collisions, and restart recovery explicitly.
- Previously published posts/images cannot be made retrospectively secret: demotion removes current public post output, but retained immutable public images and copies already downloaded remain public. Keep all never-published nonprod/draft image revisions private; sharing identical bytes with an already published image does not make those bytes private. Explicit deletion/cache purging of previously published images is an operator action outside automatic reconciliation.
- Access or an alternate URL misconfiguration can expose private output. Provision Worker-level protection before private uploads, fail closed on missing protection, verify all enabled URLs and image paths, and repeat denial checks after authenticated cache warmup. Do not use noindex as authentication.
- Private previews trade shared response caching for authenticated static HTML and small image streaming requests. Use no-store initially; measure actual private Worker/R2 usage without weakening the Access boundary to reduce cost.
- Accepted state can diverge from a deployed revision after a runner interruption. Journal candidates and compare real Cloudflare serving identities before promotion or replay.
- Public CI is unsuitable for private diagnostics, rendered nonprod artifacts, or indiscriminate SDK logging. Include canary nonprod/draft text, filenames, slugs, and unique image bytes in artifact/log/public-storage privacy tests.
- Actions and Cloudflare quotas/prices may change. Recheck current billing at rollout; keep shared commands portable and leave Cloudflare Builds as a later service choice.

## Migration Plan

1. Implement against current main using selected PR #390 code and tests. Record that the replacement supersedes the old provider/runtime plan; preserve historical QA results without relabeling them as R2 proof.
2. Provision the three R2 buckets, staging Worker/domain, targeted Access applications, dedicated credentials, and public image domain. Configure the explicitly selected owner identity and CI Service Auth policy. Prove sentinel-only staging and all PR aliases deny anonymous requests before private content is deployed. Retain existing Google/AWS data and settings as rollback material; remote-only discrepancies require operator reconciliation, not automatic deletion.
3. Migrate existing vault metadata explicitly to the two post targets. Package/configure the Mac publisher with automatic dispatch disabled. Validate manual private-source upload, image metadata, protected reports, artifact/log privacy, and plugin responsiveness.
4. Exercise local, persistent staging, and a same-repository PR with additions, overwrites, invalid edits, draft masks, deletions, promotion/demotion, missing images, and state/rollback faults. Prove protected private image HTTPS, public-media exclusion, source privacy, zero Go image-body reads, and isolation across target state. Confirm staging remains accessible after closing the PR or stopping local development.
5. After implementation merges and main's workflow is ready, run one manual reconciliation for staging and production, verify private access boundaries and both production hostnames against the target-specific receipts, then enable automatic dispatch. Switch the publisher from old Google/AWS syncing only after the R2 path passes; retain legacy resources for separate retirement.
6. To roll back, pause automatic dispatch and restore each affected target's prior Worker version and matching accepted-state receipt, verifying with the correct authentication before resuming. Preserve staging/PR Access protection, uploaded objects, and source revisions; do not delete them or change apex/www DNS as part of sync rollback.
